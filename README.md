# 双 Agent 科研协作模板

本仓库使用两个 Agent 协作科研：

- Researcher Agent 负责头脑风暴、阅读单篇论文、分析实验和创建实验。
- Coder Agent 负责初始化仓库、完善工程设计、运行实验和记录事实结果。

使用某个操作时，复制 README 中对应的 prompt；创建实验是例外，它使用后文提供的简单提示语附加到当前研究 prompt。Agent 会先读取 `researcher.md` 或 `coder.md` 的行为规范，再结合你填写的补充信息完成本轮操作。每次 prompt 以一个主要操作为主；Researcher 可在你明确要求时，把任意研究上下文中产生的实验按“1.4 创建实验”落地。

## 1 使用约定

### 1.1 文件与职责

| 文件或目录 | 用途 |
|---|---|
| `researcher.md` | Researcher 的行为规范，以及运行过程中维护的“2 论文思路” |
| `coder.md` | Coder 的行为规范，以及随 `src/` 代码和已记录实验同步维护的“2 仓库结构” |
| `papers/` | 单篇论文笔记 |
| `src/` | 完善实验设计时新增或修改的全部 Python 代码 |
| `work_dirs/YYMMDD_HHMM_xxx/` | 一个实验的目录 |
| `state.md` | 当前实验状态，只写一行 `sx 状态说明` |
| `readme.md` | 实验目的、配置、事实结果和独立分析 |
| `run.sh` | 在实验目录中直接执行的零参数入口 |
| `run_XX/` | 一次运行的产物和复现信息 |

`researcher.md` 的“2 论文思路”和 `coder.md` 的“2 仓库结构”由相应 Agent 在实际项目运行过程中按需维护；本模板不预先改写其中内容。

### 1.2 补充信息

每个 prompt 的补充区都没有固定表单。你可以自由填写自然语言、列表、链接、配置、报错或日志，也可以只写一句话。

需要操作既有实验的 prompt 会单独提供“实验目录”填写位。请在那里明确填写目标实验根目录，例如 `work_dirs/YYMMDD_HHMM_xxx/` 或其绝对路径；Agent 不扫描或猜测目标实验。其余补充信息仍可自由组织。

### 1.3 实验状态与运行目录

实验状态只描述 Coder 的执行流程：

```text
s1 待完善实验设计
s2 待运行实验
s3 实验正在运行
s4 待记录实验结果
s5 实验已完成
```

`state.md` 只包含上面某一行，不保存其他字段。正常流程是 `s1 → s2 → s3 → s4 → s5`；运行失败时由 `s3` 回到 `s1`。Researcher 的实验分析独立于此流程，不新增状态，也不修改 `state.md`。

每次运行尝试都由实验目录中的 `run.sh` 创建新的递增目录：`run_01`、`run_02`……旧目录不复用、不覆盖。编号最大的 `run_XX` 是当前结果来源，前面的目录是失败尝试的信息备份，不与最终结果聚合。一个实验成功后不再重复运行；需要验证新的科学条件时创建新实验。每次尝试实际产生且适用的模型权重、checkpoint、推理结果、测试指标、日志、退出码和复现信息都保存在本次 `run_XX` 中。

运行入口固定为：

```bash
bash run.sh
```

不传参数。`run.sh` 自行创建 `run_XX` 并维护单行 `state.md`。

### 1.4 Conda、Git 与忽略目录

具体项目使用的 Conda 环境名，由你手动填写在 `coder.md` 的“1.1.1 Conda相关”。Coder 只使用该名称；仍为 `[TBD]` 时会先请你填写。

对未被 `.gitignore` 忽略的项目文件，Agent 每完成并验证一个逻辑变更就及时提交 Git，只提交本操作产生的内容，默认不 push。`.gitignore` 中相关内容严格保持为：

```gitignore
/papers
/data
/models
/work_dirs
```

这些目录中的内容保留在本地，不强行提交，也不再添加其他相关忽略规则。

## 2 Researcher Prompt 模板

### 2.1 头脑风暴

```text
请先完整读取项目根目录的 researcher.md，并严格执行“1.1 头脑风暴”。本轮以这一项为主要操作；若补充信息明确要求，可同时按“1.4 创建实验”创建新实验。

默认只进行讨论；只有我在补充信息中明确要求写回时，才更新 researcher.md 的“2 论文思路”。讨论和写回的组织方式自由，不使用固定格式。区分已有事实、推断和待验证假设，不编造信息。

【补充信息（格式自由，可留空）】
在这里填写任何额外信息。
```

### 2.2 文献调研

```text
请先完整读取项目根目录的 researcher.md，并严格执行“1.2 文献调研”。本轮以阅读这一篇论文为主要操作，不做主题综述或多篇论文搜集；若补充信息明确要求，可同时按“1.4 创建实验”创建新实验。

根据补充信息确定这篇论文，优先阅读论文正文并核验元信息。按照 researcher.md 中原有的元信息项目生成或更新单篇论文笔记；“2 核心内容”和“3 讨论”的具体组织方式自由，不使用额外固定模板。无法取得正文或无法唯一确定论文时，说明情况并向我询问，不根据摘要编造内容。

【补充信息（格式自由；请明确一篇论文）】
在这里填写论文标题、链接、本地 PDF 路径、关注点或任何其他信息。
```

### 2.3 实验分析

```text
请先完整读取项目根目录的 researcher.md，并严格执行“1.3 实验分析”。本轮以这一项为主要操作；若补充信息明确要求，可同时按“1.4 创建实验”创建新实验。

从下方“实验目录”读取目标路径；该路径必须明确提供，不扫描或猜测。读取实验 readme.md，以编号最大的 run_XX 作为结果来源；更早的 run_XX 只用于了解失败过程。核对真实配置、日志、指标和产物；对于这个目标已有实验，只更新“4 结果分析”，具体组织方式自由，不修改“3 实验结果”、代码或 state.md，也不改变实验状态。证据不足时如实说明，不补造结论。

【实验目录（必填）】
在这里填写目标实验根目录路径。

【补充信息（格式自由，可留空）】
在这里填写任何希望补充的问题、证据、关注点或需要参考的失败 run。
```

创建实验只表示新建实验，不用于修改已有实验。头脑风暴、文献调研、实验分析或其他上下文中需要创建新实验时，不使用单独模板，直接在当前 prompt 的补充信息中加入这句简单提示即可：

```text
如果本次工作产生了需要验证的实验，请按 researcher.md 的“1.4 创建实验”创建实验。
```

## 3 Coder Prompt 模板

### 3.1 仓库初始化

```text
请先完整读取项目根目录的 coder.md，并严格执行“1.1 仓库初始化”。本轮只做这一项操作。

保留现有文件和用户改动。只使用 coder.md“1.1.1 Conda相关”中由我填写的 Conda 环境名；如果仍为 [TBD]，先请我填写。环境安装遵循该节规则；安装 pip 包时使用 `pip install -i https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple some-package`，并将 `some-package` 替换为实际包名。Git 和 .gitignore 遵循“1.1.2 Git相关”。完成检查和必要验证后，及时提交本操作中未被忽略的项目文件更新，默认不 push。

【补充信息（格式自由，可留空）】
在这里填写初始化目标、依赖、硬件、上游仓库、验证要求或任何其他信息。
```

### 3.2 查询实验状态

```text
请先完整读取项目根目录的 coder.md，并严格执行“1.2.0 查询实验状态”。本轮只做这一项操作。

从下方“实验目录”读取目标路径；该路径必须明确提供，不扫描或猜测。读取只含一行的 state.md，并核对 tmux、进程、编号最大的 run_XX、日志、退出码和必要产物。报告声明状态、实际情况、是否一致以及建议的下一操作。若状态为 s3 但进程已经不存在，根据证据将成功运行修正为 s4、将失败或中断修正为 s1；证据不足时保持 s3。其他状态默认只报告，除非我明确要求修正。

【实验目录（必填）】
在这里填写目标实验根目录路径。

【补充信息（格式自由，可留空）】
在这里填写任何希望核对的内容。
```

### 3.3 完善实验设计

```text
请先完整读取项目根目录的 coder.md，并严格执行“1.2.1 完善实验设计”。本轮只做这一项操作，不启动正式实验。

从下方“实验目录”读取目标路径；该路径必须明确提供，不扫描或猜测。完善或修订该已有实验，并可根据 prompt 或已有研究上下文中的明确决定更新“1 实验目的”；不得自行决定科学目的、主要指标或判断标准。更新“2 实验配置”和 run.sh，所有新增或修改的 Python 代码都放在项目根目录的 src/ 下；凡修改 src/ 代码，都必须同步更新 coder.md“2 仓库结构”中的 src/ 文件、目录及简短职责。安装和使用环境都遵循 coder.md 的“1.1.1 Conda相关”。run.sh 必须能在实验目录中直接零参数执行“bash run.sh”，自行创建下一个 run_XX，并保存适用的运行产物和复现信息。

完成必要验证后，实验可直接运行才把 state.md 的唯一一行改为“s2 待运行实验”；否则保持“s1 待完善实验设计”并说明问题。及时提交本操作中未被忽略的项目文件更新；work_dirs/ 中的本地文件不强行提交。

【实验目录（必填）】
在这里填写目标实验根目录路径。

【补充信息（格式自由，可留空）】
在这里填写任何实现要求、资源限制、前次错误或其他信息。
```

### 3.4 运行实验

```text
请先完整读取项目根目录的 coder.md，并严格执行“1.2.2 运行实验”。本轮只做这一项操作。

从下方“实验目录”读取目标路径；该路径必须明确提供，不扫描或猜测。若 state.md 为“s2 待运行实验”，完成最后检查后，在独立 tmux 会话中进入该实验目录，直接运行且只运行零参数命令“bash run.sh”。不要传入参数或改用其他启动命令。若状态为“s3 实验正在运行”，则检查已有运行，不重复启动。

run.sh 自行创建下一个 run_XX、保存实际产生且适用的产物与复现信息，并维护只含一行的 state.md。复现信息包括当次 run.sh 和适用配置的完整快照；做实验时不要计算、记录或使用 SHA-256。核对 tmux、进程、退出码、必要产物和状态是否一致；不要仅凭 tmux 消失判断成功，也不要覆盖或删除失败的 run_XX。脚本异常导致状态陈旧时先报告，只有我明确授权才修正。

【实验目录（必填）】
在这里填写目标实验根目录路径。

【补充信息（格式自由，可留空）】
在这里填写任何资源限制、检查重点或其他信息。
```

### 3.5 记录实验结果

```text
请先完整读取项目根目录的 coder.md，并严格执行“1.2.3 记录实验结果”。本轮只做这一项操作。

从下方“实验目录”读取目标路径；该路径必须明确提供，不扫描或猜测。只根据编号最大的 run_XX 中真实存在的日志、指标和产物，填写 readme.md 的“3 实验结果”；更早的 run_XX 是失败尝试备份，不与最终结果聚合。记录必要的 run ID 和证据路径，不填写或修改“4 结果分析”，不代替 Researcher 作科学解释。同时更新 coder.md 的“2 仓库结构”：在 work_dirs/ 下列出本次实验目录和一句简短实验目的，只具体到实验目录，不展开其内部文件或 run_XX。记录完整后把 state.md 的唯一一行改为“s5 实验已完成”；证据不完整时保持“s4 待记录实验结果”并说明缺口。

【实验目录（必填）】
在这里填写目标实验根目录路径。

【补充信息（格式自由，可留空）】
在这里填写任何指标、结果文件、需要引用的失败 run 或其他信息。
```

## 4 推荐工作流

1. Coder 初始化仓库。
2. Researcher 头脑风暴、逐篇阅读论文或分析已有实验，并在任意研究上下文中按需创建实验，状态为 `s1`。
3. Coder 完善实验设计，状态变为 `s2`。
4. Coder 在实验目录中通过 `bash run.sh` 运行实验，脚本创建新的 `run_XX`，运行期间为 `s3`，成功后为 `s4`；失败则回到 `s1`。异常退出遗留的 `s3` 通过“查询实验状态”修正。
5. Coder 以编号最大的 `run_XX` 记录事实结果，状态变为 `s5`。
6. Researcher 可在有证据后随时独立分析实验；分析不改变状态。
